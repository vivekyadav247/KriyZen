- Exact archive verification (2026-11-26): the four candidate tarballs matched the SHA-512 `dist.integrity` strings in registry metadata retrieved during research. A fresh registry read was proxy-blocked, but the saved archives were installed in the isolated runtime spike using a preserved lockfile. Candidate manifests are Apache-2.0, publish no `engines.node` field, and align declared plugin peer ranges.
- Exact core `dist/db.d.ts` defines `CorsairDatabaseInput = Pool | ...` importing `Pool` from `pg`. Its runtime adapter checks that the object has `query()` and `connect()` and constructs `new Kysely({ dialect: new PostgresDialect({ pool }) })`; runtime spike queries confirmed the shared `pg.Pool` worked with Corsair and Drizzle. P03.2 confirmed construction/import compatibility in KriyZen without a DB connection; the application has no Corsair client or separate pool lifecycle yet.
- Core's `CORSAIR_CORE_TABLE_NAMES` is exactly `corsair_integrations`, `corsair_accounts`, `corsair_entities`, `corsair_events`, and `corsair_permissions`, with declarations for all five. Exact `setupCorsair` introspects tables and warns for missing ones, then creates integration/account rows and DEKs. It does not create table DDL. Its `createTestDatabase()` helper creates only the first four tables in in-memory SQLite and omits permissions; it is not a production initializer. Inspected package exports/files contain no migration CLI/runner or vendor migration history. The official five-table PostgreSQL DDL was applied and tested only in the disposable spike database; all catalog/schema and setup checks passed. Recommend independently versioned vendor SQL/history outside KriyZen's Drizzle config/history.
- Exact Gmail `0.1.13` factory defaults to OAuth 2.0 and embeds only `https://www.googleapis.com/auth/gmail.modify`. Calendar `0.1.10` embeds `https://www.googleapis.com/auth/calendar.events` and `https://www.googleapis.com/auth/calendar.freebusy`; this differs from the broader scopes listed in current plugin setup docs. Reconcile requested operations and least privilege before consent setup.
- Core `0.2.33` exports `generateOAuthUrl` and `processOAuthCallback` from `./oauth`. Self-managed flow requires tenant ID + redirect URI, returns HMAC-signed state, and callback requires the matching redirect URI; the optional `hubConnect` option changes the flow. `processOAuthCallback` documents code exchange and encrypted token persistence. Hub is not mandatory for this SDK OAuth path, though Hub remains a hosted alternative with separate terms/cost. No real OAuth was run.

Install scripts were disabled; core's inspected postinstall fetches checksum-verified `frpc` into the user cache, an optional tunnel dependency not needed for this spike.
